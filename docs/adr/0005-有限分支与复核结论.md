# ADR 0005 · 结果服从选择：有限分支、v2 回传过渡与复核结论（v4）

日期：2026-10-30 ｜ 状态：已采纳

## 背景

审判会（2026-10-30）验收暴露三类问题：澄清选择不影响结果（不同选项生成同一条固定意图）；版本对照页省略了任务派发到 v2 回传的交代，AI 判断缺乏依据展示；覆盖判断只能循环切换、无法表达人工改判，完成摘要与最终记录不一致。修改方向：结果服从用户选择、讲清 v2 来源与 AI 依据、改判入口明确、完成态按最终记录计算。

## 决策

1. **有限分支**：澄清不是自由生成，而是一棵预先写定的有限分支树。每个选项对应各自的 Outcome（意图文本、时间码、任务标题、对照页标注与时长上限、导出文案），用户选择一路贯穿到下游。
2. **v2 回传过渡**：进入版本对照页即触发「修改人员交回 v2」的状态转换——任务状态从「修改中 / 待处理」翻转为「已完成，已交回 / 已交回，待复审」，配通知条与一次性提示。灰阶分镜与结论解耦：页面明示分镜仅用于定位示意，配音情绪、口型等结论以复核结论为准。
3. **复核结论模型**：覆盖判断改为逐条显式选择（已覆盖 / 部分覆盖 / 未覆盖）；AI 初判保留展示，人工改判后标注初判来源，分歧可附一句话依据；延期事项记为后续处置，不计入已覆盖。右栏、主区域完成小结与导出说明共用同一份最终记录。

## 理由

- 确定性演示要求结果可复现，但仍须体现「人的选择决定结果」；有限分支是两者兼顾的最简结构。
- 产品立场是「AI 辅助核对、人做最终结论」；改判必须可见、可留痕，不能掩盖素材事实与结论的差异。
- 完成态是验收叙事的收口：数量必须来自最终记录，且区分「已生成说明」与「客户已收到」。

## 影响

- 数据与状态重构：`app/src/data/mock.ts` 的 Outcome 模型；`app/src/state.ts` 新增动作 quick-confirm / cov / cov-reason / v2-returned / mark-copied。
- 深链语义更新：`#/compare` 与 `#/played` 的预置数据均为 v2 已交回状态；`#/played` 为完成态（已覆盖 3 · 部分覆盖 1 · 未覆盖 1，处理说明已复制）。
- 术语表新增「复核结论」「延期处置」（见 GLOSSARY.md）。
- 自动化回归套件（34 项）覆盖主路径、分支路径、直达链接、提示关闭与 1280 视口。
