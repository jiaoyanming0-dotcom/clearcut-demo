# ADR 0007 · 演示默认成功，失败分支按需复现

日期：2026-10-31 ｜ 状态：已采纳 ｜ 补充 ADR 0001、0006

## 背景

此前「生成修改任务」第一次必定模拟超时，再由人点「重试生成」。审判会后用户裁定：正常演示路径应直接成功，不把异常当作必经步骤；失败提示与原地重试能力保留，用于说明产品的异常处理。

## 决策

- 默认路径：点「生成修改任务」直接进入加载并成功派发。
- 失败分支：地址带 `?fail=1` 时，第一次生成模拟「生成服务超时」，任务区原地显示原因与「重试生成」，临时提示不带操作；重试即成功，已确认意图保留。
- 直达链接（`#/played`、`#/compare`）始终为已派发状态，不进入失败分支。
- 本地演示进度版本号升到 6，旧进度重置一次。

## 影响

- `app/src/state.ts`：失败门控改由地址参数决定；失败态界面、重试逻辑与提示文案不变。
- README 推荐路径与回归脚本（`docs/qa/v5flow.cjs`）同步。
