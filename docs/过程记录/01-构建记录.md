# 剪意 ClearCut Demo · Phase 1 构建记录

日期：2026-10-28

依据：`调研/03-Demo规格.md`、`demo/00-构建任务书.md`。本次仅修改 `demo/` 内文件。

## 完成项

- 新建 Vite + React + TypeScript 工程，提供 `dev`、`build`、`preview` 命令。`build` 先运行 `tsc -b`，再生成生产包；依赖清单与锁文件均已生成。未引入 UI 库、图标包、外部字体或外部媒体资源。
- `src/styles/tokens.css`：中性灰表面层级、青蓝主色、覆盖绿、部分琥珀、未覆盖灰、错误红；系统字体，正文 13px，辅助 11–12px。`src/styles/app.css`：顶栏及三栏布局、紧凑卡片、滚动区域、键盘焦点样式。
- `src/domain/types.ts`：意见、澄清配置、意图、任务、版本、时间线标记、覆盖状态、视图、步骤、决策及应用状态类型。意见状态为“待澄清 / 已澄清 / 已建任务”；覆盖状态为“已覆盖 / 部分覆盖 / 未覆盖”。
- `src/domain/data.ts`：5 条意见、5 条意图、5 组澄清配置（各两问，意见 1 保留规格中的三选一首问）、3 张任务卡、v1/v2 时间线与覆盖数据、客户处理说明全文，以及低置信度、任务失败和完成态文案。原规格提供的意见、意图、任务标题、处理说明均保持原文。
- `src/domain/reducer.ts`：初始状态、收件箱与版本对照切换、进入澄清占位、返回及重置。初始 EP13、澄清步骤、5 条待澄清意见；意图、任务、覆盖和决策为空。切换标签不会推进业务步骤。
- `src/domain/persistence.ts`：localStorage 保存、恢复和重置；无效 JSON、无效视图/意见、版本不匹配或存储访问失败均回退初始状态。写入失败不阻断当前会话。Phase 1 只持久化本期可变的视图与当前意见；后续业务字段和校验需随 Phase 2 动作扩展，已留 TODO。
- `src/components/`：TopBar、Sidebar、Workspace、OpinionCard、ReviewPanel、PhasePlaceholder 独立组件。顶栏包含项目、角色、步骤和重置；侧栏含 EP11–EP15、EP13 新意见红点、灰态术语库；收件箱完整展示来源、中英语言、文字/语音标签、正文、收件时间、时间码、状态及澄清入口；右栏展示线程信息、意图空态、任务和决策占位。
- 版本对照及澄清面板均只有标题与“待 Phase 2”说明；任务与决策区同样明确占位。未制作虚假播放帧、任务生成结果或完成态。EP11/12/14/15 没有对应演示数据，入口禁用。
- 增加本地 SVG 站点图标，消除浏览器默认请求 favicon.ico 产生的 404。

## 遗留问题与规格边界

本期没有阻断构建或骨架使用的问题。以下原规格差异保持原样，未擅自修改；进入 Phase 2 需在业务流中处理：

1. 意见 1 原文写“第 3 集”，项目与意图写 EP13。当前保留两者，后续澄清时应明确确认集数。
2. 意图 1 要求“8 秒内”，v2 结果写“8.2 秒”但标为“已覆盖”；数据保留原判定，后续版本验收需处理该阈值差异。
3. 意图 2 的 v2 初始判定为“部分覆盖”，客户处理说明固定文本写“已处理”；后续导出需与最终改判或保留判定保持一致。
4. 演示路径先处理意见 1–3，但第三张任务关联意见 5；完成态又写“5 条意见已闭环”，而结尾意图仍未覆盖。Phase 2 需明确意见 4/5 的处理路径，并区分“反馈已回复”和“修改已全部完成”。
5. 规格未提供精确收件时间，当前统一显示脚本中的“周一早上”；意见 3 在人工定位前显示“待定位”，避免提前把澄清结果当成原始时间码。意见 2–5 的追问和英文译文按规格要求补配；只存于数据层，尚未开放交互。
