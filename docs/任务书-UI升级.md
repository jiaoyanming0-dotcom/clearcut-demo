# 任务书：剪意 ClearCut Demo · UI 升级与重新上线

> 2026-10-28 深夜。用户要求任务书先行：本文件经过目后再开工。词汇以 `GLOSSARY.md` 为准，相关决策见 ADR 0001–0003。本机未配置 issue tracker，按项目惯例落盘为任务书文件。

## 问题陈述

Demo 功能完整、交互已验证，但视觉仍带模板感：卡片化过重、近黑底配单一蓝色主色、圆点串接的元信息、等宽字体被滥用在各类小标签上。这些是通用生成式界面的典型特征，与"短剧出海审片"的业务气质脱节。评审与面试场景里，界面本身也在被当作产品判断力的一部分考察。

## 解决方案

一次视觉系统升级，信息架构与交互逻辑冻结不动。四个动作：

1. 重做设计令牌：暖调深色画布、场记黄主色、发丝分隔线替代卡片框、更明确的字阶；
2. 状态表达从彩色胶囊迁移到行首状态轨与标记形式，减少装饰性色块；
3. 把"模糊意见到精确修改意图"的澄清转换做成产品的签名视觉时刻；
4. 清理界面文案与元信息连接符，统一语气。

## 用户故事

1. 作为制片统筹，我想一眼分清哪几条意见已澄清、哪几条待处理，以便决定先做什么。
2. 作为制片统筹，我想在澄清一条意见后立刻看到"那句话变成了什么可执行的任务"，以便确认 AI 理解对了。
3. 作为制片统筹，我想在版本对照里一眼看出 v2 对每条修改意图的覆盖情况，以便判断能否交付。
4. 作为制片统筹，我想在改判覆盖状态时看到 AI 初判仍然保留，以便之后复盘。
5. 作为制片统筹，我想在导出前看到客户将收到的处理说明长什么样，以便放心点导出。
6. 作为演示评审者，我想不看说明就能在三分钟内走通主流程，以便验证产品价值。
7. 作为演示评审者，我想在加载、失败、结果不理想时看到明确的下一步动作，以便不怀疑产品可靠性。
8. 作为演示评审者，我想在 1280 宽的窗口里没有横向滚动、各面板独立滚动，以便正常浏览。
9. 作为演示评审者，我想一键重置回初始状态，以便重复体验。
10. 作为用户，我想界面尊重系统的"减少动态效果"设置，以便长时间盯屏不累。
11. 作为演示评审者，我想键盘也能完成主流程的关键操作，以便不依赖鼠标。
12. 作为演示评审者，我想界面文案说清楚"发生了什么、下一步做什么"，以便不猜。

## 实现决策

### 设计方向（frontend-design 第一轮方案，含自查修订）

- **色彩**：画布 `#0D0F14` 胶片黑；面板 `#141821`；浮层 `#1B2029`；发丝线 `#242A36`；文字暖白 `#ECE8E1`，次级 `#A9B0BF`。主色为**场记黄 `#E8A33D`**，取场记板、录影提示灯、字幕标记的行业意象，替代通用的亮蓝。语义色保留：已覆盖 `#46C08A`，部分覆盖与主色同族但以"半标记"形式区分，未覆盖 `#6E7686`。
  - 自查修订：原案"近黑底加单一亮色"与"蓝色主色"都属于通用默认组合；修订为暖调文字与暖主色配对、主色意象来自业务本身（场记与字幕），且状态不再全部依赖色块胶囊。
- **字体**：受"无外部资源"约束，使用系统字体栈。数字统一 `tabular-nums`；时间码按轨道数据排版，字距与颜色克制；层级靠字重与字距建立，不用全大写、不在标题上叠装饰标签。
- **布局**：三栏骨架不变。卡片框改为"行＋发丝分隔＋行首 3px 状态轨"；右栏面板改为粘性小标题加分区分隔；对照帧按场记贴纸处理，角落标签与时间码条；时间线与覆盖矩阵沿用现有信息结构。对齐一律左对齐，正文行长受控。
- **原则**：唯一的高亮时刻留给澄清转换，即原句到意图卡的一次性生成动效；其余动效只回应操作（状态变化、toast、弹层）；悬停不做位移动效。
- **文案**：句子式、动词开头、一个元素只做一件事；元信息去掉圆点串接，改用间距与发丝分组；错误提示说明发生了什么与如何重试，如"任务生成失败：服务超时"配重试入口。

### 模块边界

- 设计令牌层（色彩、字阶、间距、动效时长）：全局重写。
- 工作台框架（顶栏、剧集侧栏、审片线程面板）：视觉重做，信息不变。
- 三个核心视图（意见收件箱、澄清视图、版本对照）：视觉与微交互重做。
- 状态机与确定性 Mock 数据：不动，仅清理文案。
- 持久化、重置、导出文本生成：不动。

## 测试决策

- 好测试的标准：只验外部行为，即界面呈现与流程结果，不测实现细节；UI 不写视觉快照与脆弱 DOM 结构测试。
- 验收方式与既有的验证缝一致：真实浏览器走查主流程、三类异常态与完成态；1600×900 与 1280×720 两档视口检查无横向滚动、面板独立滚动、键盘焦点可见、`prefers-reduced-motion` 生效；线上版本与本地一致。
- 复用已建成的脚本化点击走查：逐轮重跑并断言状态文本。
